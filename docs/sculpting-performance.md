# Sculpting performance pass

The freeze came from synchronous terrain work: each brush refresh recreated all 32 contour meshes and triggered scenery refreshes on the browser's main thread. Hosting changes do not move this client-side computation off the user's device.

## Changes

- Terrain geometry is generated by a dedicated browser worker. Typed geometry buffers transfer back to the main thread.
- Only thresholds affected by changed samples and their neighbours are regenerated. This accounts for interpolated contours beside tall cliffs, not just the edited cell's own layer.
- Unchanged mesh objects are retained. The worker queue holds one active job and one replaceable latest snapshot. Outdated results cannot overwrite newer edits or an undo/import.
- Scenery refreshes are deferred until sculpting and pending geometry finish. The settlement remains paused until its visible terrain catches up.
- Terrace bevel detail is reduced from three segments to one. Heights, smooth horizontal contours, colours and one-layer sculpting/navigation remain unchanged.
- Pixel ratio is capped at 1.35 instead of 1.7, and shadow maps update at eight times per second instead of every frame.
- Environments unable to start a worker retain a synchronous fallback. They still benefit from reduced geometry detail, but may still pause while rebuilding.

## Evidence and limits

A local CPU benchmark of a sample edit near (-4, 3) measured the previous full rebuild at 435 ms, with 2,701,380 vertices. The revised full rebuild measured 232 ms and 1,349,412 vertices; rebuilding just the two affected bands measured 22 ms. This is one local workload, not a browser FPS measurement or a guarantee for all edits and devices. Large edits affecting many levels take more worker time.

All 104 automated checks passed, including full/partial geometry equality, unchanged mesh retention, tall-cliff interpolation, queued edit coalescing, cancellation and fallback. Type checking and production build passed. The emitted worker asset was executed in a separate Node worker using a browser-message adapter and successfully returned transferable typed buffers. No browser visual or frame-rate profiling was performed.

Initial world generation, undo/import's synchronous full rebuild, save serialization and some scenery work still run on the main thread. If noticeable stalls remain, those are the next profiling targets; moving hosts is not a substitute for that work.
